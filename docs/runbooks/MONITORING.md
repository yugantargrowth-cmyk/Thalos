# Runbook: Health Checks & Monitoring

## 1. Endpoints Overview

| Service | Port | Endpoint | Description | Expected Status |
|---------|------|----------|-------------|-----------------|
| THALOS API | 3000 | `GET /health` | API Liveness probe | 200 `{ status: "ok", service: "thalos-api" }` |
| THALOS API | 3000 | `GET /health/ready` | API Readiness probe (DB + Vault) | 200 `{ status: "ready" }` (or 503 if DB failed) |
| THALOS Worker | 3001 | `GET /health` | Worker Liveness probe | 200 `{ status: "ok", service: "thalos-worker" }` |
| THALOS Worker | 3001 | `GET /health/ready` | Worker Readiness probe (DB + Vault) | 200 `{ status: "ready" }` (or 503 if DB failed) |

## 2. Metrics to Monitor
1. **API Error Rates:** Count of HTTP 5xx responses per minute. Alert threshold: > 1%.
2. **Correlation Tracking:** Correlation IDs are propagated via `x-correlation-id` and `x-request-id` headers in all responses.
3. **Queue Latency:** Difference between `created_at` and `started_at` in `jobs` table.
4. **Dead Letter Queue Count:** `SELECT count(*) FROM dead_letter_jobs;` Alert if > 0.
5. **Memory Usage:** Monitor Node process RSS memory; alert if > 400 MB.

## 3. Log Redaction Verification
Logs generated by `winston` in `src/lib/logger.ts` automatically redact passwords, API keys, PIN hashes, and Authorization Bearer headers before outputting to stdout.
Do not bypass the logger by using `console.log` directly in server modules.
