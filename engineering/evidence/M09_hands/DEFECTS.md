# DEFECTS REGISTER & RESOLUTION: MISSION S04 — HANDS

| Defect ID | Description | Root Cause | Resolution | Verification |
|---|---|---|---|---|
| **D-S04-01** | `loadToolSpecs` returned tools requiring unconfigured integrations to LLM agents | `loadToolSpecs()` queried `.in('status', ['available', 'configured', 'operational', 'needs_configuration'])`, causing tools in `needs_configuration` (e.g. unconfigured Resend or n8n) to be presented as callable. | Removed `needs_configuration` from query; only `['available', 'configured', 'operational']` tools are loaded. | Verified in `tests/contract/toolContracts.test.ts`. |
| **D-S04-02** | Missing output schemas and formalized contracts for tools | Tool metadata was fragmented between SQL seed scripts and `TOOL_PARAMS` input schemas without explicit output schemas or versioned contracts. | Introduced `ToolContract`, `TOOL_OUTPUT_SCHEMAS`, and `TOOL_CONTRACTS` in `src/intelligence/toolRegistry.ts`. | Verified in `tests/contract/toolContracts.test.ts`. |
| **D-S04-03** | Lack of declared adapter for reserved automation tools (`n8n_trigger`) | `n8n_trigger` was seeded in the database `tools` table but missing from `HANDLERS` in `toolDispatcher.ts`. | Added a declared adapter stub for `n8n_trigger` in `HANDLERS` explicitly explaining it is reserved and currently disabled. | Verified in `tests/contract/toolContracts.test.ts`. |
| **D-S04-04** | Missing server-side user role verification on sensitive tool calls | Tool dispatch verified agent permissions and approval requirements, but did not check caller `user_role` before executing high-permission tools. | Added server-side role check rejecting `guest` or `unauthenticated` roles when `tool.permission_level >= 2`. | Verified in `tests/contract/toolContracts.test.ts`. |
| **D-S04-05** | Tool results lacked consistent `tool_id`, `correlation_id`, and `timestamp` fields | Return objects from `executeTool` returned partial subsets depending on error vs success branches. | Unified all return paths under `makeResult()` ensuring fully normalized response structure. | Verified in `tests/contract/toolContracts.test.ts`. |
