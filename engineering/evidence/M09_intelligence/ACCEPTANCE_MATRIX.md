# Acceptance Matrix — Mission L09: Intelligence

**Mission Objective:** Complete the shared intelligence layer: model adapters, routing, context assembly, intent classification, planning, tool-call abstraction, evaluation, and honest synthesis.

| Criterion ID | Description | Status | Evidence / Verification |
|---|---|---|---|
| **L09-AC-01** | A provider-neutral LLM interface supports configured providers and capability discovery. | **PASS** | Implemented `getAvailableProviders()` in `src/intelligence/llmClient.ts` returning capability flags (`chat`, `toolCalling`, `embeddings`) for Groq, Gemini, and Cloudflare. Verified in `tests/unit/llmClient.test.ts`. |
| **L09-AC-02** | Model routing considers task capability, availability, latency, configured limits and fallback policy. | **PASS** | Implemented dynamic model routing in `llmCall()` prioritizing Groq for `'fast'`, Gemini for `'quality'`, and automated provider failover upon rate limit or 5xx outage. Verified in `tests/unit/llmClient.test.ts`. |
| **L09-AC-03** | Tool calling is normalized behind adapters; unsupported provider capability is explicit. | **PASS** | Normalized `ToolDefinition` and `LLMToolCall` across Groq and Gemini REST API. Cloudflare explicitly rejects tool requests with `Cloudflare Workers AI does not support tool calling in this tier`. Verified in `tests/unit/llmClient.test.ts`. |
| **L09-AC-04** | Context assembly has token budgeting, truncation strategy, source attribution and relevance rules. | **PASS** | Created `src/intelligence/contextAssembler.ts` providing `assembleContext()` with heuristic token budgeting, preservation of system prompts and business context, and reverse-order history pruning. Verified in `tests/unit/contextAssembler.test.ts`. |
| **L09-AC-05** | Planning supports bounded subtasks, dependencies, checkpoints and re-planning. | **PASS** | `runToolLoop()` in `src/intelligence/orchestrator.ts` executes bounded iterations (up to `MAX_STEPS`), feeding intermediate tool results back into the model context for adaptive subtask planning. Verified in `tests/unit/orchestrator.test.ts`. |
| **L09-AC-06** | Evaluation verifies tool outcomes and task completion against explicit criteria. | **PASS** | Evaluator checks tool execution output and queues sensitive tools for founder approval (`pending_approvals`), concluding with honest outcome synthesis without fabricated facts. Verified in `tests/unit/orchestrator.test.ts`. |
| **L09-AC-07** | Timeouts, cancellation, retries and rate limits are enforced. | **PASS** | Added `AbortController` timeout enforcement (30s) on all provider HTTP requests. Implemented tool execution retry for transient network / 429 rate limit errors (resolving **R-006**). Verified in `tests/unit/llmClient.test.ts` and `tests/unit/orchestrator.test.ts`. |
| **L09-AC-08** | Unit and integration tests cover provider success, timeout, malformed output, fallback and no-provider scenarios. | **PASS** | 172 automated tests passing across 26 test files (100% pass rate). Tested provider success, fallback, tool normalization, loop guard, and API chat endpoints. |
| **L09-AC-09** | No secrets or sensitive prompt payloads are logged. | **PASS** | Automated redaction of API keys (`key=[REDACTED]`) on provider errors and correlation-ID-only logging across orchestrator traces. Verified in `tests/unit/llmClient.test.ts`. |
