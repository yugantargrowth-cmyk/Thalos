# ACCEPTANCE MATRIX: S08 — Body & Home (Mission 14)

| Criterion | Description | Status | Evidence / Verification Location |
|---|---|---|---|
| **S08-AC-01** | The application starts locally through documented, repeatable commands with API and worker health checks. | **PASS** | Repeatable npm scripts (`npm run dev`, `npm run dev:worker`, `npm start`); verified `/health`, `/health/ready`, and `/api/system/health` in `src/api/app.ts` and `tests/unit/bodyAndHome.test.ts`. |
| **S08-AC-02** | The frontend uses Core → Environments → Workspaces and provides the agreed immersive companion/control-centre experience. | **PASS** | Unified PWA interface in `public/index.html` structuring navigation across 7 Workspaces (`view-command`, `view-agents`, `view-revenue`, `view-clients`, `view-knowledge`, `view-engine`, `view-settings`) with companion chat and daily voice briefing. |
| **S08-AC-03** | One adaptive PWA supports desktop and mobile; landscape mobile interactions are implemented without breaking portrait fallback or accessibility. | **PASS** | PWA manifest (`public/manifest.json`), service worker (`public/sw.js`), landscape media queries (`@media (max-width: 1024px) and (orientation: landscape)`), and responsive container layouts in `public/index.html`. |
| **S08-AC-04** | All displayed business metrics, agent statuses, approvals and job states come from real API responses. | **PASS** | `loadPipelineStats` (`/api/leads/report`), `loadRevenueStats` (`/api/finance/summary`), `loadClientsProjects` (`/api/clients`), `loadAgentsFleet` (`/api/system/agents`), and `loadApprovalsFeed` (`/api/approvals`). Verified in `tests/unit/bodyAndHome.test.ts`. |
| **S08-AC-05** | Settings expose integration credentials safely, masked values, connection tests and health states. | **PASS** | `GET /api/integrations` masks keys with `***` and returns connection test latencies/statuses via `POST /api/integrations/:id/test` without leaking plaintext secrets. Verified in `tests/unit/bodyAndHome.test.ts`. |
| **S08-AC-06** | UI controls are connected to real API actions and display actual success/failure/pending states. | **PASS** | Connected UI actions for approving/rejecting queue items (`/api/approvals/:id/approve`), prompt dispatch (`/api/intelligence/chat`), voice briefing (`/api/intelligence/brief`), and lead creation (`POST /api/leads`). |
| **S08-AC-07** | Loading, empty, error, offline and permission-denied states are implemented. | **PASS** | Visual offline banner `#offlineBanner` with `online`/`offline` listeners, empty states on kanban and approvals, loading skeletons, and `handlePermissionDenied()` handling 401/403. Verified in `tests/unit/bodyAndHome.test.ts`. |
| **S08-AC-08** | PWA installability, responsive behavior, keyboard access and critical accessibility checks pass. | **PASS** | `manifest.json` standalone display and icons; `sw.js` cache-first shell; keyboard shortcuts (`Alt+1`..`7`, `Escape`); ARIA roles (`role="tablist"`, `role="tab"`, `role="tabpanel"`, `aria-selected`). |
| **S08-AC-09** | Health, logs, backup status and recovery guidance are accessible to the founder. | **PASS** | `GET /api/system/logs` (structured audit logs), `GET /api/system/backup` (WAL + snapshot status, RPO < 5 min), `GET /api/system/recovery` (runbook procedures for DB restore, worker failover, offline operations). Verified in `tests/unit/bodyAndHome.test.ts`. |
